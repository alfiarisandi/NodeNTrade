## 2. Current Architecture

Alur aktual berdasarkan source code. Setiap tahap mencantumkan file dan fungsinya.

```
scripts/run_bot.py --live ── run_forever.ps1 (Task Scheduler "TradingBot", AtLogOn, auto-restart)
        │
        ▼
LiveBot.run() → step() tiap ±20 dtk                                  src/bot/live.py
  ├─ account(), DailyGuard.update (hari UTC, di memori), DrawdownGuard (journal)   risk.py
  ├─ manage_setup_positions  (BE 1R, kunci 0.5R @1.5R, parsial @1R atau $10, trail M15)
  ├─ manage_limit_orders     (terisi → trade; kedaluwarsa/berita/rugi harian → cancel)
  ├─ sync_closed_trades      (profit bersih semua deal posisi; jeda 3 rugi beruntun)
  ├─ poll_confirmations      (callback Telegram → execute_confirmed / place_limit)
  ├─ [per simbol, bar H4 baru] process_symbol → compute_features → signal_at (Ichimoku)
  │        → check_new_trade (maks 3 posisi, 1 per pair, eksposur) → review Claude → tombol risiko
  ├─ maybe_scheduled_analysis   (jam 15..23 WIB, Sen–Jum) ─┐
  ├─ maybe_watch_triggers       (close M15 kena level)     ├─► cmd_analysis → run_analysis
  ├─ maybe_screener             (15:00–23:59 WIB; A–E aturan M15 → kandidat) ─┘     │
  │                                                                                   ▼
  │     build_analysis_context (H4/H1/M15/M5, struktur, level, intraday, kalender) → Claude (9Router,
  │     cadangan Sonnet → big-pickle → DeepSeek) → parse_analysis (Setup / Opportunity / Watch)
  │                                                                                   │
  │     offer_setups: validate_setup (RR bersih ≥ 1.3, skor ≥ 60, biaya ≤ 15% R, SL 0.3–3 ATR,
  │       zona ≤ 1 ATR) → ev_block (EV forward ≤ 0 @ ≥ 20 trade) → confidence ≠ Low → kuota →
  │       active_setup_block (1) → entry_block (kill switch, jeda, pause, rugi harian, DD, spread,
  │       check_new_trade) → news_block (1 j / 0.5 j) → tombol risiko tier (0.25% / 0.5%)
  │       → record_setup / record_opportunity (tabel opportunities)
  ├─ resolve_shadows (sinyal tak dieksekusi; bar H4 + exit Ichimoku — juga untuk setup AI)
  └─ resolve_opportunities (tiap bar M15 baru; simulasi zona → SL/TP)
Telegram: notifier.py (getUpdates polling, offset di memori)    Jurnal: journal.py (signals, trades,
equity, state, opportunities)                                    Backtest: backtest/engine.py, scripts/
```

**Titik berhenti utama, yaitu kondisi yang membuat peluang tidak berlanjut ke tahap berikutnya:**
- Di luar jam aktif, screener dan analisis otomatis langsung kembali tanpa mencatat apa pun.
- Analisis dalam masa cooldown 180 detik.
- Batas 12 analisis pemicu per hari.
- AI menjawab WAIT.
- Setup gagal `validate_setup`, `ev_block`, confidence Low, kuota, `active_setup_block`, `entry_block`, atau
  `news_block`.
- Saat konfirmasi: harga sudah melewati SL/TP, RR bersih kurang, atau harga sudah bergerak lebih dari 0,5 ATR
  (khusus Ichimoku).

**Penanganan error:**
- Error di `step()` dihitung. Lima error berturut-turut mengaktifkan kill switch, dan `run_forever` me-restart
  bot.
- Screener, laporan candle, dan penilaian peluang dibungkus `try` supaya tidak ikut memicu kill switch.

## 4. Opportunity Detection Analysis

**Mandatory gates vs supporting evidence vs invalidating (di kode, bukan di prompt):**

| Jenis | Kondisi | Lokasi |
|---|---|---|
| Mandatory | SL/TP di sisi yang benar, RR bersih ≥ 1,3, biaya ≤ 15% R, SL 0,3–3 ATR H1, zona ≤ 1 ATR, skor ≥ 60, EV forward tidak negatif (≥ 20 trade), confidence ≠ Low, kuota, 1 setup aktif, kill switch / jeda / pause / rugi harian / DD, spread, 1 posisi per pair + eksposur, berita 1 jam / 0,5 jam | `analysis.validate_setup`, `live.offer_setups/offer_setup/entry_block`, `risk.check_new_trade` |
| Supporting | context, structure, liquidity, price_action, location, rr (skor) | Prompt + `SETUP_SCORE_WEIGHTS` |
| Invalidating | `invalid_level` pantauan (close M15 melewatinya), `invalid_if` setup (teks saja, tidak ditegakkan kode) | `Watch.invalidated` |

**Regime:**

| Regime | Sudah ada | Celah (kemungkinan false negative) |
|---|---|---|
| TREND | Aturan A (EMA + ADX + PA), C (VWAP), D (ORB), dan Ichimoku H4 terpisah | Ichimoku tidak masuk snapshot AI, padahal prompt menyebutnya (M3). Breakout-retest di luar range Asia/London/NY tidak punya aturan. |
| REVERSAL | Aturan B (sweep → displacement + BOS/CHoCH → FVG/OB) | Hanya B. Screener meloloskan B di regime TREND/RANGE saja (`REGIME_STRATEGIES`); MIXED = tidak ada kandidat aturan sama sekali. |
| RANGE | Aturan E (Bollinger + RSI) di screener. Strategi R (range H1) hanya di prompt AI, tanpa versi aturan. | R tidak bisa dideteksi screener, sehingga hanya muncul bila AI sedang dipanggil. |

**Kesimpulan:**
- Deteksi AI tidak lagi menuntut semua konfirmasi (prompt 16/11).
- Deteksi aturan (screener) masih sempit: A–E, satu arah sesuai regime, MIXED kosong.
- Deteksi aturan juga hanya aktif 15–24 WIB, dan tidak mencatat apa pun di luar jam itu.
- Jumlah peluang valid yang terlewat: **NOT ENOUGH DATA**, karena jurnal peluang baru ada sejak 16/11 dan belum
  berjalan di PC produksi.
